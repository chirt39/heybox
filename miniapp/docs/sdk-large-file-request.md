# 小黑盒 SDK 能力请求草稿：大文件分段读取

目标：小黑盒小程序工坊私密反馈工单。**尚未提交。**

- SDK：`@heybox/hb-sdk` 0.9.3。
- 目标平台：Android、iOS、Windows；真实客户端版本及文件能力仍待实机验收。
- 场景：玩家选择本机《艾尔登法环 黑夜君临》的 `NR0000.sl2`，小程序在本机解析遗物与战绩。用户报告其文件大于 8 MiB。
- 现状：公开 `files.pickFiles` 返回的 `FileHandle` 只提供 `readBytes()` / `readText()` 整体读取；官方文件指南规定完整读取上限为 8 MiB，`FileHandle` 未提供带偏移和长度的分段读取接口。小程序现提供本机 `.sl2` 切片脚本，按每片 7 MiB 生成 `.part` 文件，用户通过 `multiple: true` 一次选取整组分片后，在当前设备内顺序读取、拼回并交给原有只读解析器；端内拼接上限为 64 MiB，原始存档不上传。此绕行方案仍要求用户在电脑上先运行切片脚本，故原生分段读取仍可减少操作步骤和端内内存峰值。
- 请求：提供受原文件选择授权约束的只读分段接口，例如 `readBytes({ offset, length })`，并明确单段上限、总文件上限、授权失效和跨平台错误语义。原始文件应只留在用户设备，不经过应用后端。
- 预期收益：大于 8 MiB 的游戏存档可以直接导入，减少跨网站导出步骤；分段读取也可限制内存峰值。
- 验证情况：已核对 SDK 0.9.3 的公开 TypeScript 接口和 2026-10-23 更新的官方 Markdown 文档；小程序离线构建及 Browser Mock 页面加载通过。大文件在真实 Host 上的失败日志尚无，故本请求是新增能力建议，不宣称已复现 SDK 缺陷。
