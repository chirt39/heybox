# 阶段计划与任务入口

计划以验收门槛推进，不以日历日期承诺游戏数据已经正确。总控对话负责更新状态；每项工作在 GitHub Issue 或 PR 中链接需求 ID。

| 阶段 | 产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| 0. 建立基线 | 恢复线上 v41 文件、初始化 GitHub、整理需求与来源、标记当前部署 | GitHub 可读取；源码与恢复版本逐文件一致；不含个人存档或密钥 |
| 1. 需求定稿 | 用户审核 P0/P1/P2、页面流程、词条及怪物数据边界 | 关键决策写入 `DECISIONS.md`，每项 P0 有验收标准 |
| 2. 数据与接口 | 怪物、遗物、存档、规则的数据字典及样例 | 模块间 ID 和字段契约稳定；不确定字段有状态 |
| 3. 分工实现 | 各专项分支、PR 与变更说明 | 变更通过各自验收，跨模块文件由总控协调 |
| 4. 集成验收 | 真实授权样本核对、PC 页面检查、错误路径与隐私检查 | `QUALITY.md` 的发布门槛达成；已知问题有公开说明 |
| 5. 公开发布 | 对应 Git SHA 的 Sites 版本、发布记录、回退点 | 部署成功；访问路径与数据版本核对 |

## 首批待办

1. `BASE-01` 确认 GitHub 基线与线上 v41 的文件一致，并建立 GitHub 到 Sites 的受控发布流程。
2. `DATA-01` 建立怪物记录的来源和校对状态，优先处理用户指出的 Boss 魔火雷圣倍率。
3. `SAVE-01` 为遗物和日志建立字段证据表：样本值、游戏截图、解析值、偏移与版本。
4. `REL-01` 审计局外词条分类及负面词条分组、遗物图片和名称映射。
5. `BLD-01` 用复仇者兽爪蜗规则核对目标词条与评分解释。
6. `UI-01` 固定 PC 页面布局与设计规范，先处理内容裁切、分页位置和空白分配，再做装饰性调整。Vue 3 + JavaScript + Vite 基础迁移已开始；交互控制器后续按页面逐项迁入 Vue。
7. `EDIT-01` 把存档编辑作为单独验收项目：备份、受支持版本、导出后重新解析及游戏内复核。

## 当前发布链路

网站仍发布在 Sites。GitHub 是今后开发的主仓库；首次建库**不改变线上部署**。在 `BASE-01` 完成前，不能假定 GitHub push 会自动上线，也不能在多个对话中直接发布。发布负责人要记录 GitHub SHA、Sites 版本号、静态数据快照和回退方式。
